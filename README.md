# 知序 · 软件工程课程智能学习辅助系统

面向软件工程课程的学习辅助平台，提供课程管理、练习与测验、AI 错误诊断和五阶段学习引导。

前端使用 Vue 3、TypeScript、Vite、Element Plus；后端使用 FastAPI、SQLAlchemy、Alembic，支持 SQLite 和 PostgreSQL。

## 功能状态

| 功能 | 当前状态 |
| --- | --- |
| 账号与课程 | 支持教师/学生登录、课程成员管理、章节和知识点维护，按身份与课程控制访问。 |
| 知识点小练习 | 支持教师创建、学生作答、AI 诊断、回复追问及教师查看提交情况。每个知识点限一道练习。 |
| 课程测验 | 支持单选、多选、判断、填空，包含时限、次数限制、服务端判分、错题自动诊断和历史恢复。 |
| 5E 学习 | 支持从测验错题和知识点小练习的诊断进入，自动带入原题、原答案和此前诊断；按回答质量推进五阶段，支持查阅讲义后继续、恢复会话，以及完成后回看原题、继续练习和查看报告。 |
| 综合学习诊断 | 汇总同一学生、课程和知识点的近期记录，区分客观正确率、AI 暂估掌握度与行为观察，支持证据核对、历史记录和失败重试。 |
| 课程答疑与讲义阅读 | 预置课程支持内置讲义原文阅读、章节目录和检索答疑，回答引用可定位原文章节；相关模拟历史可作为上下文，页面明确标记。 |
| 学习报告与教师看板 | 学生报告默认展示真实四维画像与测验记录；有效综合诊断更新掌握度，正确率独立统计，未采集指标显示未知。支持基础先修路径、E7 时间预算策略、剩余步骤、历史及采用反馈；教师看板聚合真实记录，模拟历史需显式选择。 |

教师端不提供独立的单题诊断演示页；教师在课程小练习中查看提交与需关注情况。学生可在课程内完成小练习并查看诊断；开启 `ENABLE_DEV_ROUTES` 时，旧版单题诊断演示及记录页也仅对已登录学生显示。旧版演示记录使用固定模拟身份，不属于当前学生的正式学习档案。

教师工作台提供课程管理、课程讲义、测验管理和教师看板；学生专用的课程答疑、5E引导、个人学习报告、作答与成绩入口不在教师端显示。教师打开个人学习报告旧链接时会转到对应课程的学情看板。

学生可在测验结果或小练习的诊断下点击“针对这道题学习（5E）”。当前配置了教学模板的五类知识点支持此入口，其他知识点保留诊断与追问。从诊断进入后，系统校验作答归属和知识点，并固定保存当时的原题、原答案及诊断，供后续各轮引导参考。完成评价后可回看原题；该知识点有小练习时可再次提交练习。测验原始答案与成绩保持不变。

5E 按课程目录的章节选择知识点，并列出对应讲义及具体小节；从课程目录、讲义或错题进入时会选中对应知识点。讲义中的学习入口只展示已绑定的知识点，未配置 5E 的讲义会明确提示。新会话保存配套小节原文，供模型与知识点定义一起参考。预置讲义共六份，包含新增的自编软件测试配套讲义；课程目录仍以教师实际配置的章节和知识点为准。

学习报告新增最近 5E 学习记录。完成页进入报告后会选中对应知识点；点击“分析最近学习记录”可将新一轮 5E 作答纳入综合诊断，已有报告保留生成时的证据快照。

课件/视频上传解析、真实播放/阅读行为采集、独立题库组卷和知识图谱可视化尚未完成。先修关系、基础路径与 E7 预算推荐已实现最小版本，正式规模和真实教学评测仍待完成。测验不包含主观题 AI 评分；题目可额外标记前置检查目标。

综合诊断的计数和时间顺序由程序核对，建议与追问使用已检查的迁移任务，AI 原稿保留供复核。行为模式有依据时，知识掌握度仍可为“未知”；未采集行为数据时不推断学习投入。

## 安装与启动

以下命令在 Windows PowerShell 中执行，需要 Git、Python 3.11+ 和 Node.js/npm（本机已验证 Node 22，Node 16 无法构建当前前端）。

### 1. 获取代码并安装依赖

```powershell
git clone https://github.com/sickQC/segongcheng.git
cd segongcheng
powershell -ExecutionPolicy Bypass -File .\scripts\setup.ps1
```

已有克隆先保存自己的修改，再拉取要体验的分支的最新提交。依赖或前端有更新时，重新运行安装脚本。

### 2. 配置环境

在项目根目录执行，已有 `.env` 时保留原配置：

```powershell
if (-not (Test-Path -LiteralPath .env)) { Copy-Item -LiteralPath .env.example -Destination .env }
```

编辑 `.env`：

- `SEED_PASSWORD`：设置至少 8 位的本地测试密码，用于首次创建演示账号。
- 数据库：快速体验可删除 `DATABASE_URL=...` 整行，使用默认的 `backend/learning.db` SQLite 文件；不要设为空值。使用 PostgreSQL 时，先创建数据库和角色，再填写自己的连接地址。
- 模型：按下方“模型配置”填写。未配置模型也能使用课程、作答、判分和历史记录。

本机配置、数据库、登录状态、虚拟环境和前端构建产物不会随 Git 克隆。

### 3. 初始化并启动

在项目根目录执行：

```powershell
.\.venv\Scripts\python.exe -m alembic -c backend/alembic.ini upgrade head
.\.venv\Scripts\python.exe scripts/seed_data.py
.\.venv\Scripts\python.exe scripts/build_rag_index.py
powershell -ExecutionPolicy Bypass -File .\scripts\start.ps1
```

打开 <http://127.0.0.1:8000>。以后启动只需运行 `scripts/start.ps1`；该脚本自动迁移数据库并幂等回填历史有效综合诊断的掌握度，不重置账号或重新生成种子。

讲义正文或元数据有更新时，重新运行 `scripts/build_rag_index.py` 并重启服务，使新增讲义、检索索引和 5E 小节绑定一起生效。

初始化创建 `teacher`、`student01`、`student02`，以及一门课程、两章四个知识点。初始密码为自己设置的 `SEED_PASSWORD`；重复初始化不会修改已有账号密码。小练习和测验需由教师创建。

如需展示有数据的教师画像看板，可额外运行：

```powershell
.\.venv\Scripts\python.exe scripts/seed_teacher_demo.py
```

脚本在预置课程中增加 `demo_student_01` 至 `demo_student_10`（密码使用本地 `SEED_PASSWORD`）、8 份模拟测验和 7 份模拟小练习。重复运行不会重复添加或覆盖已有记录。模拟学习事件带 `synthetic=true`，不进入正式综合诊断；教师看板默认排除模拟作答，演示时打开“包含模拟数据”开关。演示数据在本机数据库中，不会随 Git 推送。

若 8000 无法绑定，完成初始化后可在根目录改用以下命令，访问 <http://127.0.0.1:8765>：

```powershell
$env:ALLOWED_ORIGINS='["http://127.0.0.1:8765","http://localhost:8765"]'
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8765
```

使用相对 SQLite 地址时，迁移、初始化和服务须保持一致的工作目录；默认绝对路径不受此影响。切换到 PostgreSQL 不会自动导入 SQLite 数据。

## 模型配置

在 `.env` 中填写，修改后重启后端：

```dotenv
LLM_API_KEY=填写自己的APIKey
LLM_BASE_URL=https://api.deepseek.com
LLM_MODEL=deepseek-flash
C_LLM_BACKEND=api
C_LLM_MODEL=
```

`LLM_*` 用于课程答疑等模型调用；`C_LLM_*` 配置练习诊断、测验诊断、综合诊断和 5E。使用 API 时，`C_LLM_MODEL` 留空则沿用 `LLM_MODEL`。模型服务须支持 `/chat/completions` 和 JSON 输出，基础地址不要重复包含该后缀。

模型不可用时，答案与客观分数仍保存，失败诊断可重试；5E 的真实反馈与阶段推进需要可用模型。共享部署使用 API，各自的密钥填写在被 Git 忽略的 `.env` 中。

当前统一使用 DeepSeek API：课程答疑、练习诊断、测验诊断、综合诊断与 5E 均使用 `deepseek-flash`。保持 `C_LLM_BACKEND=api`、`C_LLM_MODEL` 留空即可共用 `LLM_MODEL`。克隆项目后须填写自己的 DeepSeek API Key，并完成前述数据库初始化；本机密钥、账号登录状态和学习记录不会随仓库分发。

## 基本使用

登录后打开“软件工程基础”，保持“真实接口”模式。

| 入口 | 使用流程 |
| --- | --- |
| 课程目录 | 教师维护章节、知识点和课程成员；学生浏览已加入的课程。新建课程需先添加学生成员。 |
| 知识点小练习 | 教师添加简答题 → 学生提交 → 查看诊断并回复追问；教师可查看提交情况。 |
| 课程测验 | 教师录入题目、标准答案与解析后发布 → 学生开始、交卷 → 查看成绩及错题诊断。标准答案填写完整选项文本，多选每行一条。 |
| 资源学习 → 课程答疑 | 在讲义列表点击“阅读原文”，查看标题、表格、代码和章节目录；选择具体讲义后提问可限定范围，回答中的引用可定位到对应章节。“全部内置讲义”可检索全部6份讲义。 |
| 资源学习 → 5E 引导 | 按课程章节选择知识点，查看对应讲义小节后开始；也可从讲义或错题诊断进入。按当前任务回答，最后完成小测并解释依据。刷新后可恢复历史。 |
| 个人学习报告 → 综合学习诊断 | 先完成练习、测验或 5E，再选择知识点分析最近 30 天的记录；可核对证据、查看历史并重试失败任务。可用证据不足时掌握度显示“未知”。 |
| 教师学情看板 | 选择近 7/30/90 天，查看班级提交和知识点测验正确率；筛选待关注学生，点开原答案、诊断与证据，必要时生成综合诊断。无作答显示“暂无证据”，模拟记录单独标记。 |

5E 和综合诊断的迁移任务已配置五个知识点模板，种子课程默认包含其中四个；体验边界值模板时，教师需新增编号为 `KP-BOUND-01` 的“边界值分析”知识点。更新后的诊断规则用于新生成的报告，已有历史报告保留原样。

“界面预览”使用样例数据，不保存作答、不调用模型。个人学习报告默认“真实学习记录”；选择“模拟历史演示”才展示旧模拟数据及其演示助手，不参与真实画像。真实画像区可按知识点查询事件，综合诊断成功后自动刷新掌握度。
