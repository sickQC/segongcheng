# D：E7 多种子离线对照实验

本阶段补规划中的 E7 可复现对照、重复运行和均值/区间报告。没有修改推荐公式或业务页面，不访问业务数据库，不调用模型，不生成真实账号或学习记录。

## 固定设计与复跑

配置：`data/eval/recommendation/e7-experiment.json`。程序：`scripts/eval_e7_experiment.py`。本轮结果：[完整 JSON 报告](../evaluation/e7-multiseed.json)。

```powershell
.\.venv\Scripts\python.exe scripts/eval_e7_experiment.py
```

默认输入和结果写入 D 盘项目 `.local/ci/e7-experiment-input.json`、`.local/ci/e7-experiment.json`。CI 已接入相同命令，文件随后端报告上传。复跑的调度输入、选中路径及非计时指标应一致；真实测得的调度耗时会变化，因此整个报告文件不会逐字相同。

实验在运行前固定配置，未根据测试集结果调整算法。20 个开发场景和 80 个测试场景使用不重叠的种子范围。每场景独立生成 30 节点、40 条边的无环图；先生成连接到目标的随机树，再补随机前向边。它们是算法输入，不是软件工程课程的真实教学先修关系。

四种合成输入分布为大部分掌握度未知、偏薄弱、混合、大部分已掌握；测试集每种 20 场景。每种分布配合 10/20/40/80/160 分钟预算，估时在 3–25 分钟随机取值。目标掌握度固定未知，确保比较待学任务。其余掌握度是合成的“算法可见观测”，不是独立潜在真值，更不是实际学习效果。

两策略使用相同输入、目标、预算、掌握阈值和估时，复用现有正式调度代码及原评测器。每场景两策略各预热一次，再实际运行 5 次，交替执行顺序；共 1,000 次计时调度，另有准备/校验调用。完整输出与第一次结果比较，检查确定性。每次计时只覆盖纯调度，不包含数据库、HTTP、建图、模型或学生学习。

独立检查预算、全部未掌握祖先的顺序；检测到违规或重复运行结果变化，脚本以非零状态退出。报告保存逐场景选中/剩余步骤、估时、实际调度计时、配置、输入 SHA256、相关源码和依赖锁 SHA256，以及 Python/系统信息。

## 区间口径

每个指标以场景为统计单位；5 次调度不是 5 个独立学生样本。均值区间使用固定种子的 2,000 次场景重采样，取排序后重采样均值的 2.5%/97.5% 分位位置。策略差异先在同一场景内计算 `E7 - baseline`，再对这些成对差值重采样。分布内及总体结果分别报告。

这是描述当前合成生成器抽样差异的简单百分位 bootstrap 区间，不是对真实学生总体的保证，也没有做多指标显著性检验。计时区间同样只描述本轮机器与场景下的纯调度。百分位与成对重采样口径可参考 [SciPy 官方 bootstrap 文档](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.bootstrap.html)；本实现使用标准库，没有新增 SciPy 依赖。

## 本轮结果（2026-10-19）

80 个测试场景：

| 指标 | baseline | E7 |
| --- | ---: | ---: |
| 平均安排步数 | 3.900 | 5.425 |
| 平均计划估时（分钟） | 51.550 | 54.238 |
| 平均预算利用率 | 68.55% | 81.14% |
| 计划包含目标比例 | 6.25% | 6.25% |
| 先修违规 / 预算违规 | 0 / 0 | 0 / 0 |
| 真实接受率 / 实际学习耗时 | 未测 | 未测 |

E7 相对基础策略平均多安排 1.525 步，成对差值的合成场景区间为 `[1.275, 1.7875]`；预算利用率平均增加约 12.59 个百分点，区间约 `[6.46, 19.29]` 个百分点。开发集两策略也无约束违规。

E7 同时平均使用了更多估计时间，不能把它表述成“学习更快”。在固定闭包与固定成本下，完成整个目标所需的全部任务与总成本相同；本轮两策略计划包含目标的比例完全相同。优先级本身使用薄弱程度和估时，因此这些合成指标也不能作为独立教学质量依据。

本轮实际通过原 E7 与新增实验相关 **27 项测试**，随后对最终脚本再跑新增 **8 项测试**通过；Ruff 和更新后的 CI actionlint 检查通过。没有重新执行全仓测试或前端构建；上阶段全仓 261 项通过的记录仍保留为历史。本轮修改仅为离线脚本、配置、测试、报告、CI 和文档。

## 仍然没有证明的事项

- 100 个场景不是 100 个学生，不满足平台“100 人、每人 50 事件”的数据要求；此处没有制作四类学生事件模拟器。
- 30 节点/40 边的随机图不能替代真实课程内容规模或教师确认的依赖。
- 没有真实推荐采用率、学习耗时、学习增益、在线 API 延迟或完整教学实验；相关字段保持 unknown/null。
- 随机图分布、强制所有节点通向目标以及目标未知等设计会影响结果。没有保证适用于所有课程或优于其他优化算法。
- 原来的 12 个手工边界用例继续保留；本轮实验是补充，不替代业务权限、事务和边界测试。
- GitHub 云端运行仍待推送后验证；本轮没有推送代码。
