# 成员 D：基础先修路径推荐

> 本文保留第二阶段实现范围。后续已加入 E7 时间预算策略、估时与反馈，见 [第三阶段说明](e7-budgeted-recommendation.md)。旧历史快照仍按生成时规则保留。

本阶段在真实画像上新增正式先修关系及 baseline 推荐，不包含 E7 时间预算优化。沿用 Vue/FastAPI，不增加第三方依赖；本轮 npm 缓存位于 D 盘项目 `.local/npm-cache`。

## 分工边界

仓库原先没有正式课程先修关系表，只有 RAG 静态知识元数据；本阶段补齐推荐必需的最小关系表与教师表单，没有重建知识图谱可视化。未在所读文档中发现更具体的成员归属约定，后续图谱负责成员可直接接入以下接口，避免另建一套先修数据。章节顺序、RAG 元数据不会自动写成课程先修关系。

`from_kp_id → to_kp_id` 表示先学前者，再学后者。仅课程教师能维护，两端必须属于同一课程；拒绝自环和间接环，错误返回完整环路 ID 序列，页面展示知识点名称。已有相同关系的重复提交返回原关系。仍被关系引用的知识点不可直接删除，但可以编辑名称。

同一课程的关系变更、知识点删除与推荐输入读取通过数据库锁串行化，防止并发的 A→B 和 B→A 同时通过校验。SQLite 使用写锁，PostgreSQL 使用课程行锁。仅支持现有项目的两种数据库；本轮实测 SQLite，未实测 PostgreSQL。

## 算法与证据

1. 校验课程先修图，找出目标的完整先修闭包。
2. 对整个闭包按先修约束拓扑排序；多个可用节点按知识点编号和 ID 确定顺序。
3. 再跳过有效画像掌握度达到阈值的节点。先排序后过滤，避免跳过中间节点时丢失传递依赖。
4. 默认阈值 0.7，可通过 `MASTERY_THRESHOLD` 配置（可选，现有 `.env` 无需改动）。未知掌握度安排待测/待复习，不当作零分。目标本身已掌握时返回空路径及明确说明；需要复习某个先修时可单独将其设为目标。
5. 步骤附实际综合诊断 ID、输入截止时间、置信度、事件证据和推荐理由；没有诊断时明确来源为先修规则。
6. 关联实际存在的知识点定义、小练习入口，不编造视频、课件、预计用时或诊断。缺少小练习时提示教师补充。知识点链接定位课程目录中的对应卡片，练习仍由学生主动展开作答。

没有为目标配置先修关系时，仅安排目标并提示教师核对关系完整性；不能据此声称已补齐课程实际需要的一切先修。

## 保存与重试

迁移 `0009` 仅新增 `knowledge_edges`、`recommendations` 两表，不删除旧表及记录。生成使用 POST；GET 只读历史，不触发推荐或模型。

推荐请求按课程、学生、`request_id` 唯一，同一请求重试返回原快照，用同一编号改目标返回 409。推荐结果与 `recommended` 事件同一事务保存；推荐事件不计为学生实际学习投入。不同请求会按当前输入生成新快照。

历史快照保留生成时的目标、先修边、掌握度和证据；后续画像、知识点名称或关系变化不改写旧记录。历史中知识点被删除时，旧入口可能无法定位；重新生成获取当前内容。尚未增加接受/拒绝推荐反馈、自动重算和 E7 对照评测。

## 接口

所有路径前缀为 `/api/v1/courses/{course_id}`。

| 方法与路径 | 用途 |
| --- | --- |
| `GET /prerequisites` | 课程成员读取先修关系 |
| `POST /prerequisites` | 本课程教师新增 `{from_kp_id,to_kp_id}` |
| `DELETE /prerequisites/{edge_id}` | 本课程教师移除关系 |
| `POST /recommendations` | 学生为本人生成 `{target_kp_id,strategy:"baseline",request_id}` |
| `GET /recommendations` | 本人最近推荐，默认20条，最多100条 |
| `GET /recommendations/{id}` | 本人或本课程教师读取详情 |
| `GET /students/{student_id}/recommendations` | 本课程教师读取该学生历史 |

学生不得指定他人作为生成对象，不得读他人的推荐；教师不能跨课程查看。沿用现有 Cookie、CSRF 和来源检查。

新的完整路径数据由上述专用接口提供；旧 `/report` 中的 `recommendations` 字段保留为兼容布局字段，真实页面使用独立“基础先修路径推荐”组件，模拟预览仍显示样例。

## 初学者体验

1. `teacher` 登录，打开“软件工程基础”的教师课程编辑页面，在“先修关系”表单配置已确认的教学依赖。例如有 A→B、B→C，表示目标 C 依赖 A 和 B。不要仅为演示编造学科依赖。
2. `student01` 登录，进入“学习报告”，保持“真实学习记录”，找到“基础先修路径推荐”。
3. 选择目标 C，点击“生成基础路径”。无有效诊断时按 A、B、C 安排，并标明待测；有已掌握节点时跳过。
4. 点击“阅读知识点定义”或“查看配套小练习”，跳转后对应知识点卡片会突出显示。
5. 返回报告，刷新后可从“推荐历史”重新打开原路径。学习并获得新的有效综合诊断后，主动重新生成新路径。
6. 教师尝试新增 C→A，应显示具体环路且不保存该关系。

本轮没有向已有课程自动灌入先修边，没有添加模拟掌握度或学生作答；网络验收会为 `student01` 保存一条按当前真实输入生成的基础推荐，重复检查复用同一请求编号，不代表学生接受了建议。
