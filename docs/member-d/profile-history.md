# D：画像历史快照与对比

本模块对应需求规划中的 `profile_snapshots`，补齐 M9 画像的历史保存和可追溯比较，不新增资源采集、测验或模型业务。

## 行为

- 有效综合诊断真正更新至少一个知识点掌握度时，在**同一数据库事务**保存诊断、掌握投影及一份近30天四维画像快照。失败、证据不足、重复应用或旧结果未更新投影时不新增快照。
- 学生可在真实学习报告的“画像历史与对比”手动保存当前近30天结果；教师可通过API指定本课程学生保存/查询。客户端不能上传自定义掌握度或四维结果。
- 快照冻结保存时的完整画像，包括知识、投入、偏好、风险、证据和计算版本。查询时不重新计算，也不随知识点改名、事件新增而更新旧快照。没有提供修改/删除快照的API。
- 请求标识幂等；相同标识参数冲突返回409。自动和手动请求使用不同命名空间，不能互相占用标识。
- 时间显示北京时间，存储与接口统一UTC。历史支持分页、详情和两份快照的比较。
- 对比只接受同一课程学生、同窗口天数、同规则版本的两份不同快照，并按先后顺序比较。未知值不当作零；缺失任一端时差值为null。
- 变化是描述性数值：滚动窗口在移动，资源值是累计观测，不能把差值解释为实际学习增益、区间新增时长或推荐效果。

**不会回填旧历史。** 迁移仅新增表，旧报告和既有画像保持原样。没有保存时点证据就不伪造旧时刻画像；升级后的第一份快照可由用户手动保存，之后新诊断按规则自动保存。

## 使用

1. 打开原生环境 `http://127.0.0.1:8000`，用学生账号进入个人学习报告，选择真实记录。
2. 找到“画像历史与对比”，点击“保存当前画像快照”。无证据项仍应显示未知。
3. 完成新的真实学习活动，或取得有充分证据的综合诊断，再保存/刷新历史。有效诊断更新掌握度后会自动保存。
4. 点击历史时间查看冻结详情，选择较早和较晚两份快照进行比较。
5. 没有配置模型也可手动保存与比较行为/客观统计；不能为演示自动快照而伪造诊断或掌握度。

模拟历史和界面预览不出现保存入口。视频、阅读及完整偏好仍取决于真实采集，快照只保存已有结果，不填入模拟值。

## API

前缀 `/api/v1/courses/{course_id}/profile/snapshots`：

| 方法/路径 | 含义 |
| --- | --- |
| POST 根路径 | `request_id`（1–64字符，字母数字下划线连字符）、`days`（1–90整数，默认30）；由服务器计算并保存 |
| GET 根路径 | `offset` / `limit`（最多100）分页历史摘要 |
| GET `/{snapshot_id}` | 历史完整详情 |
| GET `/compare?before_id=...&after_id=...` | 两份历史四维对比 |

教师在上述请求增加 `student_id` 查询参数，必须是自己负责课程中的学生。学生只能访问本人；跨课程/跨学生快照ID不能越权使用。写请求需正常登录、同源及CSRF校验。完整schema见 [OpenAPI](../api.yaml)。

迁移为 `0011_profile_snapshots.py`，只新增 `profile_snapshots` 及索引。现有启动和容器初始化会升级到head，新表无需单独种子或批量回填。正式升级前仍应备份数据库。
