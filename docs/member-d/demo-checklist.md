# D：演示与人工验收步骤

这是供用户执行的人工步骤，**不是已经替你点过浏览器的通过记录**。开始时全部为待验；下面“预期结果”只说明应出现的行为。无需把密码、API Key或整份 `.env` 发给别人。

## 1. 现有课程快速体验

1. 浏览器打开 `http://127.0.0.1:8000/?v=d-handoff#/login`。这是原生本地环境；打不开时先按README启动，不能用VS Code编辑区的刷新快捷键代替浏览器操作。
2. 用 `student01` 登录，进入课程的个人学习报告，选择真实学习记录。
3. 查看知识、投入、偏好、风险四部分，核对证据来源；缺少数据应显示未知，不应凭空出现完成率或视频时长。
4. 查看事件列表，用知识点筛选；切换基础顺序/E7，选择目标与预算生成路径，查看剩余步骤和历史。
5. 若课程没有先修边，推荐可能只有目标一个知识点，这是数据配置尚未形成依赖，不是多分支算法的有效演示。

| 人工项目 | 预期结果 | 用户记录 |
| --- | --- | --- |
| 页面与登录 | 可打开、学生账号可登录 | 待验 |
| 真实画像 | 有来源，未知明确，无模拟历史混入 | 待验 |
| 事件筛选 | 能筛选与翻页，无他人记录 | 待验 |
| 事件导出 | CSV/JSONL下载、筛选生效、无模拟记录 | 待验 |
| 推荐与历史 | 能生成、查看来源和未安排步骤 | 待验 |

## 2. 可选的独立算法验收课程

为避免改动已有教学关系，教师可手动新建“D算法验收”课程，加入测试学生，在一个章节里新增4个知识点。以下是假设的算法输入，不能声称是正式软件工程教学依赖。助手没有代你创建这份课程。

| 编号 | 显示名称 | 教师估时 |
| --- | --- | ---: |
| D-A | 验收任务A | 18分钟 |
| D-B | 验收任务B | 4分钟 |
| D-C | 验收任务C | 6分钟 |
| D-T | 验收目标T | 5分钟 |

教师在先修编辑区添加 `D-A → D-T`、`D-B → D-C`、`D-C → D-T`。箭头含义是左边先学。通过估时编辑区分别设置表中的分钟数。使用尚无有效诊断掌握记录的学生做下面的检查。

1. 学生以 `D-T` 为目标、预算10分钟生成基础顺序：按当前编号拓扑前缀，D-A需要18分钟，预期本次无安排步骤，完整剩余路径仍可见。
2. 同一目标和预算生成E7：预期安排D-B、D-C，估时合计10分钟；D-A与D-T仍待完成，不应跳过D-A直接安排目标。
3. 将预算改为40分钟：所有步骤合计33分钟，应能包含完整目标路径；这不表示学生已完成学习。
4. 教师尝试添加 `D-T → D-B`：形成环，应被拒绝并显示环路，原有图保持不变。
5. 学生可按自己的实际意愿提交接受/拒绝反馈；刷新后仍保留。没有反馈时接受率应为未知；反馈不会增加掌握度或有效学习活动。

| 人工项目 | 预期结果 | 用户记录 |
| --- | --- | --- |
| 10分钟基础/E7对照 | 基础空前缀；E7安排B、C；目标仍未安排 | 待验 |
| 40分钟完整路径 | 包含A、B、C、T且先修顺序正确 | 待验 |
| 环路拦截 | 明确拒绝，原有关系保留 | 待验 |
| 反馈持久化 | 保留个人选择，不当作学习完成 | 待验 |

## 3. 画像更新与权限

学生完成一次教师创建的客观测验后，回到真实报告，检查客观正确率与真实事件；完成有充分证据的综合诊断后，再检查掌握度及来源更新。教师创建题目、学生真实作答和诊断属于已有功能，本次不会预填正确答案或伪造学习结果。

如果没有配置模型，客观判分仍可检查；AI诊断/5E的真实结果保持待验，不能用模拟历史来宣称真实画像通过。不能手工把掌握度改成0.9来冒充诊断已更新。

学生只能看本人记录；教师只可查询所负责课程学生。跨人/跨课程边界已有自动测试，人工浏览器验收仍需单独记录。老师的班级聚合看板与学生四维画像不是同一份页面验收。

## 4. 怎样给组员汇报

新增导出人工验收：学生在真实报告的“导出真实学习事件”中下载两种格式；教师在学生详情下载同一学生记录，核对数量与筛选。文件可能含答案原文，不要发到公开群。操作详见 [事件导出](event-export.md)。本机API已经验证，浏览器实际下载仍待用户记录。

可按这段话说明，并在实际验收后补充结果：

> 我负责了真实事件查询、画像基础计算、先修路径和E7时间预算推荐，并补了本地自动测试、CI配置、部署配置及E7离线对照。核心业务已能在本机运行。视频/阅读画像依赖资源事件对接；容器和GitHub云端尚待运行验证，真实学习效果尚未证明。人工演示结果按验收表记录。
