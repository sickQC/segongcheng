# 成员 D：真实事件与四维画像最小闭环

> 本文保留第一阶段范围。后续已实现 [基础先修推荐](baseline-recommendation.md) 和 [E7 时间预算推荐](e7-budgeted-recommendation.md)；资源采集仍需对接。公共工程进度见 [CI](ci.md) 和 [部署基础设施](deployment.md)。

本阶段在原有业务上增加真实事件查询、四维画像服务、综合诊断到掌握度的持久化投影，以及学生报告页面。基础先修路径、E7、完整资源采集、CI/CD 和全栈部署继续作为后续阶段，不计为本阶段完成。

## 数据与规则

- 所有统计按课程和当前学生隔离；仅纳入 `context.synthetic` 严格为 `false` 的真实事件，排除未分类旧事件、未来事件和窗外事件。默认统计最近 30 天，画像接口可选 1–90 天。
- 学生报告默认 `history=real`；旧模拟历史保留为显式 `history=synthetic`，只支持预置课程及两名演示学生。模拟助手仍为独立历史演示，不读取真实画像。界面预览仍为样例。
- 知识掌握：每个知识点保留最新有效综合诊断中的掌握度、置信度、来源报告、证据事件与输入截止时间。未知为 `null`。正确率独立统计近窗客观题，不等同模型掌握度。单题诊断尚不直接更新长期画像，需通过综合诊断汇总证据。
- 学习投入：北京时间的活跃天数及活动次数来自现有作答、问答和 5E 事件。资源时长/覆盖率仅接受服务端测量，按资源取最新累计快照，避免累计心跳重复相加；完成比例只表示已测资源中覆盖率达到 90% 的比例，不是全课程完成率。未接入资源生产端时显示未知。
- 活动偏好：展示视频、阅读、问答/5E、练习/测验四类。占比目前仅比较窗口内问答与练习；资源累计访问次数单列，不混入窗口占比分母，未采集显示未知。完整四类窗口偏好还需资源生产端联调；此处不推断固定学习风格。
- 风险：某知识点近窗至少 3 次客观作答且正确率低于 50%；或该点最近 3 次作答连续错误；或至少 7 天无已记录活动。显示触发原因和事件依据，无触发项且不足 3 次客观作答时为未知。未采集活动不推断实际投入不足。

## 一致性与持久化

新增迁移 `0008`，仅新增 `mastery_profiles`、`profile_applications`，不删除原数据。

`run_report` 在诊断完成事务中应用掌握度；报告应用记录唯一，按“输入截止时间、报告创建时间、报告 ID”排序执行条件 upsert，SQLite/PostgreSQL 均使用数据库冲突处理。重复执行无效，旧输入即使晚完成也不能覆盖新输入；失败、证据不足、掌握度为空及越权/模拟证据不覆盖已有掌握度。异常回滚时，诊断与画像一并回滚。

掌握度持久化；其余维度和正确率按需从真实事件实时计算，本阶段未增加四维历史快照表。保留的掌握度可能早于统计窗口，页面明确显示其输入截止时间和更新时间。

资源累计时长/覆盖率表示窗口内最后一次观测到的累计测量，不是近 30 天增量。后续资源生产端接入后，应提供窗口增量与去重的访问记录，才能补全窗口投入和四类偏好。

已有数据库升级后，运行 `python scripts/rebuild_profiles.py` 幂等回填已支持的综合诊断；`scripts/start.ps1` 已在迁移后调用该脚本，不修改历史诊断和原答案。`.env` 不需要添加字段。

## 接口

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/courses/{course_id}/report` | 真实报告，四维数据在 `learning_profile`；旧 `profile` 为兼容布局字段，不承载新结构 |
| `GET .../report?history=synthetic` | 显式模拟历史 |
| `GET .../profile?days=30` | 当前学生画像 |
| `GET .../students/{student_id}/profile?days=30` | 本课程教师查询学生画像 |
| `GET .../learning-events` | 学生查询本人；教师必须传 `student_id`，且限本课程学生 |

事件查询可传 `knowledge_point_id`、`verb`、带时区的 `start/end`、`offset/limit`（最多 100），返回 `next_offset` 和实际时间边界。查询时间范围最多 90 天；分页时复用第一次返回的时间边界。只有读取接口，不允许浏览器写入成绩、诊断或任意事件。

## 体验

1. 学生进入“个人学习报告”，默认显示真实记录。没有作答时为零次活动及未知掌握度，不展示模拟正确率。
2. 教师发布测验，学生作答；回到报告刷新，可看到客观正确率、提交历史及活动次数。三次错误可触发解释明确的风险规则。
3. 在“核对真实学习事件”中查询，按知识点筛选并展开原始事件。
4. 配置可用模型后，点击“分析最近学习记录”。有效综合诊断成功后会更新掌握度并自动刷新报告；失败或证据不足保留旧掌握度。真实模型质量须另外验收。
5. 选择“模拟历史演示”时，仅查看旧演示内容，不参与真实画像。

## 验证范围

新增测试覆盖真实测验闭环、事件筛选与分页、跨学生/课程权限、未知值、模拟排除、北京时间活跃天、资源累计快照去重、失败/不足保留、重复/并发应用、乱序完成及事务回滚。默认测试为隔离 SQLite + 模型替身；PostgreSQL 分支沿用可选独立 schema 测试。本轮不把真实模型、资源生产端或浏览器逐页操作计作已完成验收。

本机验证（2026-10-19）：通过 `scripts/test.ps1` 跑通 223 项后端测试（原 211 项 + 本阶段 12 个用例）、前端类型检查与生产构建。保留一个 TestClient/httpx 弃用警告和构建包体积提示。新增 Python 文件的 Ruff 检查通过。

现有 SQLite 已在升级前备份到本机 `.local/before-profile-*.db`，升级至 `0008` 后通过 HTTP 验证三个账号、真实报告、独立模拟历史、画像、事件查询、教师看板及前端静态资源。校验确认 `.env` 未改变、原有业务表记录数量没有减少。两名学生当前没有真实活动，显示未知掌握度符合预期；没有额外灌入演示作答。

本轮未配置真实模型、未跑 PostgreSQL，浏览器自动化没有可用连接；不宣称完成逐页浏览器验收。旧 `tests/browser-workspace.cjs` 含早期业务 501 与默认模拟报告断言，需后续整体更新，不作为本阶段的验收入口。
