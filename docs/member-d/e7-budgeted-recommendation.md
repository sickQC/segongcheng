# 成员 D：E7 时间预算推荐最小实现

本阶段在正式先修关系与真实画像上加入时间预算策略、估时来源、剩余步骤、主观采用反馈和对照评测脚本。不是强化学习，不承诺全局最优路径或真实教学效果。

## 计划规则

基础与 E7 均使用同一个目标先修闭包、0.7 默认掌握阈值、有效综合诊断和内容入口。未知掌握度仍显示未知，不作为零分。

- `baseline`：不传预算时保留完整基础路径；传入预算时，按确定的拓扑顺序保留放得下的连续前缀，遇到放不下的步骤即停止。
- `budgeted`：必须传 1–240 的整数分钟预算。每次仅从所有未掌握先修都已安排、且剩余预算放得下的节点中选择优先级最高者。
- 优先级为 `(0.6×薄弱程度 + 0.4/(1+到目标的最短先修距离))/预计分钟数`。已知薄弱程度为 `1-mastery`；未知只在排序中使用中性值0.5，不写回画像。平分时按知识点编号、ID确定顺序。
- 即使中间节点被标记为已掌握，也要保留未掌握祖先的传递约束。预算内安排是顺序执行计划，不能把“已安排”当作“实际上已学会”。
- 未安排步骤完整保留，说明预算不足或先修未安排；预算太小时可返回空计划和全部剩余项，不跳过必要先修去直接推荐目标。
- `goal_in_plan` 表示目标已掌握或计划包含目标，不代表学生执行了计划。

在当前固定闭包、固定成本模型下，两种策略完成整个目标所需的全部步骤与总估时相同。E7 的主要差别是预算不足时如何安排部分先修任务，不能声称降低了完成全部目标的必需成本。

## 估时与教师配置

知识点新增可空 `estimated_minutes`。教师在课程编辑页的“推荐学习估时”中设置1–240分钟，或恢复为规则估时；已有数据保持空值，不自动写入假耗时。

未配置时使用 `5 + 3×难度 + (有配套小练习则加5)` 分钟，标记 `rule_estimate`；教师填写时标记 `teacher`。二者都是计划估计，不是观看、阅读或作答的实测时长。每份推荐保存使用的估时，后续修改不会改写历史。

## 接口与兼容

路径前缀 `/api/v1/courses/{course_id}`。

| 接口 | 行为 |
| --- | --- |
| `PATCH /knowledge-points/{id}/study-time` | 本课程教师提交 `{estimated_minutes:正整数或null}`；null恢复规则 |
| `POST /recommendations` | 增加 `strategy=baseline/budgeted`、`time_budget_minutes`；同一请求编号不可换目标、策略或预算 |
| `GET /recommendations/{id}/feedback` | 本人或课程教师读取反馈，无反馈为null |
| `POST /recommendations/{id}/feedback` | 学生本人提交 `{choice:accepted/declined}`，教师不可代提交 |
| `GET /recommendation-metrics` | 学生看本人，课程教师看本课程两策略统计 |

旧基础请求不传策略/预算仍有效；旧历史快照可以读取，缺失估时等字段返回null，不补写伪造值。页面明确标记旧版历史。新快照含本次/完整/剩余估时、剩余步骤、估时来源、调度规则和目标是否包含在计划中。

E7 使用专用推荐接口和当前页面；旧 `/report?algorithm=enhanced` 仍是历史占位接口（501），不作为 E7 生成入口。`/report` 的兼容布局字段也不承载新的完整路径快照。

`0010` 迁移仅给知识点加可空列并创建 `recommendation_feedback`；配置文件无需增加字段，已有关系、画像与推荐保持原样。

## 反馈和在线统计

每份推荐保留一次学生意愿反馈；重复相同反馈幂等，不同选择返回409，可对新计划再反馈。反馈与 `recommendation_feedback` 事件同事务保存，不计学习投入、不改掌握度，也不等于完成任务。

接受率按“愿意采用数 / 已反馈推荐数”计算，未反馈不算拒绝，无反馈为null。展示样本数；估时均值仅统计有估时的记录。在线混合不同目标和预算，不能用该统计直接证明某个算法更好。没有代学生提交验收接受或拒绝反馈。

## 可复跑对照

```powershell
.\.venv\Scripts\python.exe scripts/eval_recommendation.py --output docs/evaluation/e7-baseline-budgeted.json
```

固定数据 `data/eval/recommendation/e7-cases.json` 含4个开发场景、8个测试场景，明确为人工编写的合成约束用例，不是学生观察数据。两个策略使用相同输入和预算，记录完整选中/剩余步骤、估时、预算利用率、计划包含目标情况，以及独立检查的先修和预算违规。

当前测试场景结果：基础平均安排1.125步、估时6.375分钟；E7平均1.5步、8分钟。平均预算利用率分别约57.14%与67.63%；两者“计划包含目标”比例均37.5%，约束违规均0。增加安排量或预算利用率不自动代表更好的学习效果；实际耗时和接受率未在合成场景中测量，接受率保留null。

这是确定规则在有限固定场景上的可重复检查，不是正式规模的泛化/教学实验。测试还覆盖20组固定随机种子的DAG约束。后续已补充 [100 场景多种子离线实验](e7-experiment.md)，含重复计时、均值和成对区间；真实学生数据规模、真实采用反馈与教学效果仍待验收。

## 体验

1. 在浏览器打开 `http://127.0.0.1:8000/?v=e7-20261019#/login`。刷新快捷键应在浏览器页面内使用，不能在 VS Code 编辑区使用。
2. 教师确认先修关系，必要时在“推荐学习估时”配置分钟数。
3. 学生进入真实学习报告，在“先修路径与时间预算推荐”选择同一目标与预算，分别生成“基础顺序”和“E7 时间预算”，从历史切换查看。
4. 预算不足时查看未安排步骤；实际学习并得到新的有效诊断后重新生成。若愿意采用，可自行提交反馈；这不会自动完成学习。
5. “查看两种策略使用统计”展示本人使用情况和已反馈接受率。正式课程若还没有先修关系，单个目标无法体现多分支调度差异，应先配置真实教学依赖。
