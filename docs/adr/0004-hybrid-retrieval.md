# ADR 0004：混合检索与本地向量后端

AI 助教（M7）的检索采用稠密向量 + BM25 双路召回，再用 RRF 融合、特征重排，最后按小节扩展上下文。
选混合而不是单路，是因为术语精确匹配（"圈复杂度"）靠 BM25，口语化提问（"什么时候该用等价值划分"）靠向量，两者互补。
RRF 只用排名不用分数，省去 BM25 分值与余弦相似度的量纲归一化。

默认向量后端是本地哈希 TF-IDF（词级 token + 中文 2-gram），不是神经嵌入。
课程要求新成员按 README 在 30 分钟内启动，而下载 torch 与中文嵌入模型需数 GB 流量；
本地后端零下载、确定性，使整套检索与评测在无网络、无 API Key 时也能复跑。
`SE_RAG_EMBED_BACKEND` 可切换到 sentence-transformers 或 OpenAI 兼容接口，切换后需重建索引。

切分按 Markdown 标题结构进行，并把定义句单独成块——定义是学生最常问的内容，独立成块才能被精确命中；
喂给模型时再扩展为同小节全文（small-to-big），引用展示仍用命中的精确片段，保证出处可核查。

同义词表里的领域术语同时注册进 jieba 用户词典，但**规范术语给最高词频、近义写法给低词频**。
两者同频会使近义写法（"代码坏味"）挤掉正确分词路径（"代码/坏味道"），反而降低召回。
