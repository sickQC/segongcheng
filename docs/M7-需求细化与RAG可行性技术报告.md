# 第一部分　可验证需求的修改完善

## 1.1 可验证的判定准则

一条需求可验证，当且仅当**存在一个成本有限的客观过程，能对"该需求是否被满足"给出是/否结论**。

按此准则，基线需求的问题集中在两处：

- **判据缺失**——如"回答正确"，但未规定真值来源；
- **口径缺失**——如"拒绝给出答案"，但未规定测多少条、达到多少比例才算通过。

# 第二部分　RAG 可行性技术报告

## 2.1 验证目标与判据

本报告要回答的问题是：**以课程讲义为唯一知识来源，能否构建一个"答得准、不胡说、可追溯、可评测"的 AI 助教检索内核。**

四项可行性判据：

1. **准确性**——课程内问题能检索到正确小节，且回答附带真实存在的出处；
2. **可靠性**——资料不足时明确拒答，不编造；对抗性输入不改变系统行为；
3. **工程性**——依赖可离线安装，流程可复现，成本可核算，调用可追溯；
4. **可评测性**——方案中的每一项设计都可通过消融实验验证其贡献。

## 2.2 技术方案

**检索链路**：稠密向量与 BM25 双路召回 → RRF 融合 → 特征重排 → small-to-big 上下文扩展。

**生成链路**：接地提示词 → 大模型生成 → 引用编号校验 → 输出护栏。

**关键设计取舍：**

| 决策 | 选择 | 依据 |
|---|---|---|
| 召回方式 | 稠密 + 稀疏混合 | 术语精确匹配靠 BM25，口语化提问靠向量，两者互补 |
| 融合方式 | RRF | 只用排名不用分数，免去 BM25 与余弦相似度的量纲归一化 |
| 切分单元 | 标题结构 + 定义句独立成块 | 定义是最常被问到的内容，独立可精确命中；父块保证生成上下文完整 |
| 拒答判据 | 实词加权覆盖率 + 关键实词命中 | 单一连续阈值不足；结构性规则不随语料规模失效 |
| 默认向量后端 | 本地哈希 TF-IDF | 免下载、免联网、确定性，保证新环境可复现 |

## 2.3 实现

知识库覆盖 5 个知识域、39 个知识点、49 条先修关系，切分为 100 个片段并建立 76 个父块。索引构建耗时 0.25 秒。交付物包括可运行的 FastAPI 服务、命令行问答工具、评测与标定脚本、51 项自动化测试，以及 RAG 策略文档。

## 2.4 结果

评测集 56 题，按 ID 奇偶确定性划分为开发集（用于标定）与测试集（用于报告）。测试集 28 题结果：

| 指标 | 结果 | 课程合格线 |
|---|---|---|
| doc_hit@3 / doc_hit@6 | 1.000 / 1.000 | — |
| term_hit@6 | 1.000 | — |
| MRR | 0.944 | — |
| 回答率（课程内问题） | 1.000 | — |
| 引用率 / 引用准确率 | 1.000 / 1.000 | 引用准确率 ≥ 0.80 ✅ |
| 正确拒答率（超范围问题） | 1.000 | ≥ 0.80 ✅ |
| 提示注入拦截率 | 1.000 | ≥ 0.90 ✅ |
| 作弊诱导拒绝率 | 1.000 | ≥ 0.90 ✅ |
| 延迟 P50 / P95 | 9.2 ms / 13.4 ms | 首字符 < 5 s ✅ |

## 2.5 结果分析

**一、拒答判据必须建立在实词上。**

仅按词覆盖率判定"资料是否有依据"，超范围拒答率只有 0.375。原因是问题中的弱词会贡献虚高分数：问"2024 年诺贝尔物理学奖颁给了谁"，"2024"和"年"恰好出现在语料中，贡献了大半个权重。

修正为 IDF 加权的**实词**覆盖率，并将三类词权重置零——纯数字、单字中文、纯提问脚手架词（"哪几个""步骤""详细"）。修正后该题相关性由 0.485 降至 0.200。

**二、单一连续阈值不足以判定可回答性。**

问"红烧肉怎么做才好吃？请给详细步骤"，真正的实词"红烧肉""好吃"一个都没命中，但泛化后缀"详细""步骤"在语料中，可凑出 35% 覆盖率。补充一条结构性规则——**问题中权重最高的两个实词至少命中一个**——后，超范围问题最高分降至 0.000，同时课程内问题回答率保持 1.000。

**三、中文领域术语必须注册进分词器用户词典，且词频需分级。**

领域术语（如"等价类划分"）若不注册，会被切成碎片，BM25 召回显著下降。但近义写法（如"代码坏味"）若与规范术语同为最高词频，会挤掉正确分词路径（"代码/坏味道"），反而降低召回。正确做法是规范术语给最高词频、近义写法给低词频。

**四、当前语料规模下消融实验不产生区分度。**

8 种检索配置（含仅稠密、仅 BM25、关闭重排、关闭同义词扩展、分块 300/800 字符、关闭父块扩展）在测试集上均达到 doc_hit@3 = 1.000、term_hit@6 = 1.000，MRR 区间 0.944–0.972。

该结果说明：在 5 篇语料、100 片段的规模下，检索难度低于各配置的能力下界，实验无法区分设计差异。**复跑判据**：语料扩展至 10 篇、片段数 ≥ 250 后复跑，以 term_hit@6 出现非满分配置作为消融实验生效的标志。

## 2.6 可行性判定

| 维度 | 判据 | 结果 | 结论 |
|---|---|---|---|
| 技术可行性 | 引用准确率、拒答率、护栏拦截率达标 | 1.00 / 1.00 / 1.00 | **可行** |
| 工程可行性 | 依赖可离线安装、流程单命令复现、自动化测试通过 | 51 项测试通过，索引构建 0.25 s | **可行** |
| 性能可行性 | 首字符 < 5 s，非智能接口 P95 < 1 s | P95 13.4 ms | **可行** |
| 成本可行性 | 可按功能核算调用次数、token 与费用 | 成本报表与 trace 已实现 | **可行** |
| 进度可行性 | 全链路可复现，无不可控外部依赖 | 通过 | **可行** |
| 风险 | 语料规模 | 当前唯一显著约束 | **可控**，见 2.7 |

## 2.7 后续工作

1. 补齐《软件测试》章节（等价类划分、边界值分析、覆盖准则），消除当前的知识库缺口。
2. 评测集扩充至课程要求规模（≥ 60 题）并冻结，随后复跑消融实验，取得有区分度的设计结论。
3. 接入真实大模型后重测延迟、token 与单次成本，替换当前离线兜底后端。
4. 与 M8 诊断智能体对接证据字段，使诊断结论可直接引用本模块的片段编号。
