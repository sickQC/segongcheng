# 综合学习诊断与评测

## 功能与使用

学生在“个人学习报告 → 综合学习诊断”选择知识点，分析最近 30 天的实际答题、练习及对话。AI 判断概念问题并暂估掌握度，服务器独立核对行为模式、生成事实说明，配套已检查的迁移任务。客观答题正确率由服务器单独计算。结果不会改分，也不写入画像或推荐。

发布测验时，教师可填写“本题检查哪个知识点的基础”。这个目标与主知识点一起冻结到题目中，客观错答可成为明确的前置检查证据；它不等同于全局先修图谱。

迁移执行 `alembic upgrade head`，新增 revision `0006` 的 `diagnosis_reports`，旧答案和会话保留。启动注册新路由，前端重新构建后可使用新入口。

## 证据与护栏

- 仅选目标学生、课程、知识点、时间窗口内的事件，`synthetic` 必须显式为 false。知识点可通过数据库 ID 或已有可读 code 匹配。
- 默认 30 天，可通过 API 设置 1–90 天；最多 20 知识点、每点最近 30 条事件，候选上限 2000 条。快照显示截断情况，不称为全量历史。
- 答题取学生原答案与服务端判分；课程答疑仅取学生提问，不把模型回复当作学生理解的证据。5E 取学生本轮回答，先前模型判断不用于制造真值。
- 创建时冻结定义、事件、基线和截止时间。先提交事务后调用模型；幂等请求返回同一报告，重试使用原快照。模型失败、跨人/跨知识点证据、伪造编号、非法输出不会写成有效诊断。启动恢复会标记中断任务，供重试。
- 注入指令从模型输入中排除，报告记录排除的事件编号；过滤后不足两条可用证据时，不调用模型，返回未知掌握度。
- 反复错误需引用至少三次客观错答，且最新客观题尚未纠正；前置缺失需引用教师标记的前置检查错答。模型仍可能判断错误，语义解释需要人工评阅。
- 不受证据支持的行为/错误模式按知识点降为 `insufficient`，保留其他有效结果，记录 `guardrail_actions`。证据不足与确定分数互相矛盾时统一为未知掌握度，也记录修正。跨人/伪造证据、提示泄露及非法结构仍拒绝整份模型结果；这些保护不修改客观分数。
- `status` 表示主要诊断的证据充分性。可信行为观察充分时，`low_engagement` / `practice_only` 可以为 `supported` 且 `mastery=null`：行为模式有依据，知识掌握度仍未知。其他 supported 类型需要有效掌握度。页面对 null 显示“未知”。
- v8 独立保存 `observed_behaviors`，不依赖模型是否能估计知识掌握度。仅使用最近的有效服务端行为汇总；窗口不完整、资源不可用或最近记录不满足阈值时不提升判断。规则补充主类型时记录 `apply_verified_behavior_rule`，不编造掌握度或置信度，`confidence` 可为 null。明确前置检查错误及反复客观错误优先于行为主类型。

播放/阅读采集尚未实现。模块不会把“没有行为记录”当成“没有学习”，也不提供客户端伪造行为的入口。为后续生产者预留的行为契约：

```json
{
  "object": {"type": "resource", "kp": ["知识点ID"]},
  "context": {"course": "课程ID", "source": "resource_tracker", "measurement": "server", "synthetic": false},
  "result": {
    "effective_seconds": 8,
    "coverage": 0.05,
    "study_visits": 1,
    "resource_available": true,
    "observation_complete": true
  }
}
```

生产者必须由服务端验证有效观看、去重覆盖和观察窗口完整性，不能直接信任浏览器提交的统计。当前只是契约和判定护栏，未标记为真实行为采集完成。低投入观察要求完整窗口、资源可用、覆盖率 ≤0.2 且有效秒数 <120；“只刷题”还需至少三次客观答题、完整窗口内学习访问为零。阈值是可解释的初版规则，不用于推断态度、智力或心理状态。

## 接口

均使用 `/api/v1` 前缀，沿用登录 Cookie、Origin/CSRF 和课程成员权限。

| 方法与路径 | 用途 |
| --- | --- |
| POST `/courses/{course_id}/diagnosis-reports` | 学生分析自己的学习记录。 |
| POST `/courses/{course_id}/students/{student_id}/diagnosis-reports` | 本课程教师为课程学生发起分析。 |
| GET `/courses/{course_id}/diagnosis-reports` | 学生读取本人最近 20 条；教师读取本课程最近 20 条。 |
| GET `/courses/{course_id}/diagnosis-reports/{id}` | 读取状态、冻结快照、结果与 trace。 |
| POST `/courses/{course_id}/diagnosis-reports/{id}/retry` | 原快照重试，仅 failed 状态允许。 |

创建体：`knowledge_point_ids`、`days`、UUID `request_id`。客户端不能指定其他学生、成绩或模型后端。JSON Schema 与错误响应见 [OpenAPI](api.yaml)。

## 数据集与人工复核

当前默认数据是 `data/eval/learning_diagnosis/v2`：100 名合成学习者、每人 50 个事件，共 5000 事件。涵盖七种候选情形：概念混淆、前置缺失、反复错误、低投入、只刷题、未见明显问题、证据不足；含 3720 段对话。按学习者 ID 分为开发 60 人、测试 40 人，包含旧错误后纠正、正确率较高但对话仍混淆等分布。父目录中的旧数据和旧评测结果保留，不用于新版评测。

数据由自编情景生成，不是真实学生数据。两组使用同一生成器和课程主题，属于按学习者分组的合成留出，尚不是外部独立教学数据。生成脚本不会把样本写入应用数据库；模型只收到 `snapshot`，不会收到候选标签或模拟掌握度。

新版 `label-review.csv` 有 300 行，以学习者 ID 和 full/no_dialogue/no_behavior 变体共同定位；每行保存实际输入快照的 SHA256。2026-10-17 用户在对话确认“我审完了，没问题”后，助手代录测试集 120 行为 `approved`，审核人为 `hermit1919`，标签未修改；开发集 180 行仍为 `pending`。记录依据及审核范围见 [人工复核确认](evaluation/test-label-review-confirmation.json)。该确认针对输入证据和候选标签，后续模型输出的解释、建议和追问需另行评分。

JSONL 中的 `label_review` 保留生成时的状态；当前审核状态以绑定同一快照的 `label-review.csv` 为准，避免为更新状态而改写冻结的输入数据。

后续复核时，应查看该变体可见的事件与上下文，修改 `expected_type`/`expected_status`，填写 `review_status=approved`、`reviewer` 和意见。证据变更后旧复核不能沿用。不要仅根据模型输出反向改标签。

初版单主类型规则：有明确前置检查错误时优先描述前置缺口；否则，满足至少三次客观错答且最新仍错时，优先描述反复错误，在解释中补充可能的概念混淆。行为类型描述完整窗口内的学习方式，可与较高掌握度并存。只说“不知道”不足以定位错误，也不能当作正确理解的证据。这些规则需由人工复核确认。

新版修正了正确回答被标为答错的样本；概念情形保留“客观题正确、解释混淆”的真实冲突。低投入情形保留一次客观错答和完整行为汇总，避免同时满足反复错误条件；只刷题情形用正确解释，区分学习方式与知识错误。

| 标签值 | 含义 |
| --- | --- |
| `concept_confusion` | 概念混淆 |
| `prerequisite_gap` | 有明确前置检查证据的知识缺口 |
| `repeated_error` | 足够且尚未纠正的反复客观错答 |
| `low_engagement` | 有服务端测量支持的低投入观察 |
| `practice_only` | 有完整观察窗口支持的答题/资源学习失衡 |
| `no_obvious_issue` | 未发现明显问题 |
| `insufficient_evidence` | 证据不足，状态须为 insufficient |

生成脚本保留已有人工复核表，不覆盖审核结果：

```powershell
.\.venv\Scripts\python.exe scripts/build_diagnosis_eval.py
```

## 评测运行

默认只跑客观正确率基线，不请求模型：

```powershell
.\.venv\Scripts\python.exe scripts/eval_evidence_diagnosis.py
```

标签复核后，使用已配置模型执行测试集、三轮重复和消融：

```powershell
.\.venv\Scripts\python.exe scripts/eval_evidence_diagnosis.py --live --repeat 3
```

默认运行 full/no_dialogue/no_behavior，移除数据后重新计算输入统计，不保留被移除来源的聚合特征。类型准确率与 macro-F1 使用各变体自己的待审/已审标签；另列 `full_label_retention_rate`，表示删减证据后仍保持完整标签的比例，它不是准确率。例如概念混淆仅体现在对话时，移除对话后正确答案支持“未见明显问题”；移除行为后不能再要求识别低投入或只刷题。

固定知识基线为客观题正确率 <0.7；二分类只评价概念混淆、前置缺失、反复错误、未见明显问题四类。行为模式不代表知识不足，证据不足也不作为已知知识真值，两者从此指标排除，并报告 eligible 数量及覆盖率。指标另含证据有效率、跨轮均值与近似区间、耗时和已返回 token；模型失败计入类型指标分母，缺费用单价显示 unknown。

服务端保守降级与模型原始通过分开统计：`guardrail_downgrades` 记录被降为证据不足的次数，`model_first_pass_valid_rate` 不把降级算作模型原始通过。问题分类分数使用最后展示的结果，证据有效率检查事件范围；后者不能代替语义证据充分性。

少于两条可用证据时，服务器直接返回未知，不请求模型。当前工具另列 `pipeline_successes`、`model_calls`、`local_insufficient_results`，避免把本地拒答计为模型成功；usage 覆盖率以实际模型尝试为分母，失败调用的缺失用量不按零计费。

标签未复核时，正式模式会拒绝运行。需要检查模型联通和输出时可显式使用临时模式，例如：

```powershell
.\.venv\Scripts\python.exe scripts/eval_evidence_diagnosis.py --live --provisional --limit 7 --repeat 2
```

该命令使用固定分层子集，报告标记 `provisional_not_formal_acceptance`。少量重复的正态近似区间仅作描述，不作为可靠总体推断。评测保存数据、提示、标签表的 SHA256；结果在 `.local/evidence-eval.json`，复跑会消耗模型额度。

`--data-dir` 可指定同版本的独立数据目录。模型不可用、登录缺失、额度限制或 CLI 配置失效时，工具记录首个失败并立即停止，`run_complete=false`，不继续重复请求。模型返回非法 JSON/字段时，错误详情只保留阶段、字段名和校验类型；不保存原始错误输出中的凭据、路径或学生文本。

Windows 本机 Codex 模式下，`C_CODEX_BINARY` 留空会优先发现桌面应用自带 CLI，再尝试全局安装；显式配置的路径不存在时明确报错，不悄悄回退。调用失败区分登录、额度、模型不可用、连接和参数错误；未识别原因仍标为 unknown。不自动替换模型或循环重试。CLI 参数和配置行为参见 [官方 CLI 文档](https://learn.chatgpt.com/docs/cli/reference)。

## 输出复核问题修复（v8，2026-10-17）

当前提示为 `evidence-diagnosis-v8`，展示规则为 `diagnosis-presentation-v1`。本轮修改实际生成流程，v7 原始测试、审核记录和95%类型指标保留。

| 复核问题 | 实现处理 |
| --- | --- |
| 低投入与未知掌握度混淆 | 用已有的完整测量独立核实行为模式；模型拒答或漏判时规则可补充行为主类型，掌握度仍未知，修正有单独记录。 |
