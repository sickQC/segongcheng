## 1. 目标与约束

RAG 层要同时满足两类互相拉扯的要求：

**要"答得准"**
- 回答必须**基于课程资料**，并给出**可点击核查的出处**（AC-M7-1）；
- 问答要能定位到知识点，供 M8 诊断与 M9 推荐复用。

**要"不胡说"**
- 资料里没有的问题必须**明确说明没有依据**，不许用先验知识编造（AC-M7-2）；
- 测验进行中索要答案必须拒绝（AC-M7-3）；
- 课件里夹带的"忽略以上指令"不得改变智能体行为（AC-M3-4 / AC-NF-10）；
- 回答里的引用编号必须真实存在（AC-NF-12）。

**还要满足工程约束**
- 新环境 30 分钟内能跑起来（AC-NF-16）→ 默认不依赖任何需要下载数 GB 的模型；
- 每次调用可 trace、可核算成本（AC-NF-14 / AC-NF-4）；
- 检索设计必须可做**消融实验**（《实践项目要求》第 6 章）。

一个关键的现实约束来自课程本身：**内容来源只有《软件工程》课程资料**，不存在通用百科式的兜底。因此"拒答"不是可选项，而是系统正确性的一部分——一个在课程范围内乱答的助教，比一个会说"资料里没有"的助教危害更大。

## 3. 知识库与语料规范

**目录结构**
```
kb/
├── docs/SE-01-overview.md        # 讲义正文（Markdown）
└── meta/SE-01-overview.md.json   # 知识点元数据（name/definition/difficulty/bloom/prereq_names）
```

**为什么正文与元数据分离**
正文给人和大模型读，元数据给知识图谱与推荐算法读。分开后，教师改讲义不需要动结构化数据，`E5 图谱智能构建` 也可以只产出候选元数据、交给教师审核后合入。

**语料写作约定（直接影响检索质量）**
1. 每个概念**定义独立成段**——切分器会把定义句单独抽成 chunk，使"X 是什么"类问题的精度显著提高；
2. 每个知识域必须有一节 `## 常见误解与易混淆概念`，采用 `❌ 错误理解 / ✅ 正确理解 / 辨析` 三段式。这一节是**诊断型智能体（M8）识别概念混淆的主要证据来源**，也是学生提问"X 和 Y 有什么区别"时最直接的答案；
3. 每个知识域必须有一节 `## 与其他知识域的关系`，说明先修与后续，供 M9 推荐路径使用；
4. `## 参考来源` 小节**不进入索引**——URL 列表会污染检索结果，只保留在文档里供人核查。

**知识点挂接**
切分完成后，先按"知识点名称在小节标题/正文中出现"做字面挂接；对仍然孤立的知识点，用「知识点名称+定义」的向量在全部 chunk 中检索，取最相近的 2 个 chunk 兜底挂接。这样保证 **AC-M4-5（每个知识点至少关联 1 个资源）** 成立。本项目 39 个知识点中有 16 个是通过语义兜底挂接的。

## 4. 切分策略

| 决策 | 取值 | 理由 |
|---|---|---|
| 切分单元 | 标题层级 → 段落 | 讲义天然有层级，按结构切能保证语义完整 |
| 目标长度 | 500 字符 | 中文 500 字符约等于一个完整小节 |
| 重叠 | 80 字符 | 防止答案正好横跨切分点 |
| 上限/下限 | 900 / 80 字符 | 超长强制再切，过短与邻块合并 |
| 定义句 | **单独成块** | 定义是最常被问到的内容，独立成块可被精确命中 |
| 父块 | 同小节全文 | small-to-big 用（见 §8） |

**为什么不用固定长度切分**
固定长度切分会把"定义"和紧跟着的"例子"割裂到两个 chunk。检索时命中定义块，但生成的上下文里没有例子，回答就会显得干瘪；反之命中例子块又会缺失定义。按结构切 + 定义句独立成块，让"小块检索、大块生成"成为可能。

**内容类型标签**
每个 chunk 会打上 `kind`：`definition / body / procedure / method / example / pitfall / relation`。这个标签在重排时作为先验特征使用（`pitfall` 与 `definition` 权重最高），因为它们在课程答疑中信息密度最高。

## 5. 索引与向量嵌入

### 5.1 双索引

- **稀疏**：`rank_bm25.BM25Okapi` over jieba 分词结果；
- **稠密**：嵌入向量余弦相似度（向量已 L2 归一化，内积即余弦）。

### 5.2 嵌入后端可插拔（消融维度）

| 后端 | 说明 | 适用场景 |
|---|---|---|
| `hashing`（默认） | 词级 token + 中文 2-gram，双哈希到 1024 维，IDF 加权 | 离线开发、CI、评测基线；**零下载、确定性** |
| `st` | `sentence-transformers`，如 `BAAI/bge-small-zh-v1.5` | 需要更强语义召回时 |
| `openai` | 任意 OpenAI 兼容 `/embeddings` | 生产环境 |

切换只需改 `SE_RAG_EMBED_BACKEND`，重建索引即可。**默认选哈希 TF-IDF 而不是神经嵌入，是一个明确的工程取舍**：课程要求"新成员 30 分钟内在本地把系统跑起来"，而下载 torch + 中文嵌入模型通常需要数 GB 流量和数分钟；离线后端让整套 RAG（含评测与消融）在无网络、无 API Key 的环境下也能端到端跑通。

### 5.3 中文分词的坑（实测踩过）

jieba 会把"边界值分析"切成"边界/值/分析"，导致 BM25 命中率下降。解决办法是把同义词表里的**领域术语注册为 jieba 用户词**。

但这里有一个反直觉的坑，值得记录：

> 起初把同义词表的**键和值都**以最高词频注册。结果问"什么是代码坏味道"，分词变成 `代码坏味 / 道`——因为值里的近似写法"代码坏味"被注册成了同样高频的词，把 `代码 / 坏味道` 这条正确路径挤掉了。
>
> 修正：**键给最高词频（2,000,000），值只给低词频（10,000）**。

### 5.4 归一化的坑：不能用全局 NFKC

起初用 `unicodedata.normalize("NFKC", text)` 做全角转半角，结果**中文标点被一并折叠**（`：`→`:`、`，`→`,`、`（`→`(`），展示给学生的引用片段变成了西文标点，读起来很别扭。

实际需要的只是让 `ＩＳＯ ２５０１０` 与 `ISO 25010` 等价，因此改为**只折叠全角字母与数字，中文标点原样保留**（`textutil._FULLWIDTH_FOLD`）。

## 6. 查询理解

1. **归一化**：NFKC 全角转半角、统一小写、压缩空白。保证 `ISO/IEC 25010` 与全角写法等价。
2. **分词 + 停用词**：去掉中文功能词与疑问词（"什么""如何""请"）。疑问词必须去掉，否则"什么是 X"会大量命中"什么"。
3. **同义词/缩写双向扩展**：`config/synonyms.json` 中，键命中则加值、值命中则加键。学生说 `SRS` 也能召回写着"软件需求规格说明"的段落；说"内聚"也能召回 `cohesion`。
4. **提问脚手架词提取**：识别"哪几个""步骤""详细""举例""常见""组成"等**只表达提问意图、不含主题信息**的词（见 §10.3）。

## 7. 混合检索与 RRF 融合

**为什么必须混合**

| 场景 | 纯 BM25 | 纯向量 |
|---|---|---|
| "圈复杂度怎么算"（术语精确匹配） | ✅ 强 | 一般 |
| "我搞不清什么时候该用等价值划分"（口语化） | ❌ 差 | ✅ 较好 |
| 术语在语料里写作英文缩写 | ❌ 差 | 一般 |

因此两路并行召回（各取前 30），再用 **RRF（Reciprocal Rank Fusion）** 融合：

$$\text{score}(d) = \sum_{l \in \{dense, sparse\}} \frac{w_l}{k + \text{rank}_l(d)}, \qquad k = 60$$

RRF 只用**排名**不用**分数**，因此不需要对 BM25 分值与余弦相似度做量纲归一化——这是工程上最省事也最鲁棒的融合方式。

检索还支持**元数据预过滤**（`doc_ids` / `kp_ids`），对应"在某个知识点下提问"的场景，并为 M9 的路径推荐预留接口。

## 8. 重排与上下文组装

### 8.1 重排特征

| 特征 | 含义 | 权重 |
|---|---|---|
| `rrf_norm` | 归一化后的 RRF 分数 | 0.34 |
| `wcoverage` | 实词加权覆盖率（§10.1） | 0.26 |
| `coverage` | 普通词覆盖率 | 0.14 |
| `phrase` | 最长公共子串 / 查询长度（奖励原句命中） | 0.14 |
| `kind` 先验 | definition/pitfall 0.95~1.0，body 0.7，relation 0.5 | 0.12 |

在语料规模扩大、需要更强重排时，这里可以无缝替换为 cross-encoder（如 `bge-reranker`）；`RetrievalConfig.use_rerank` 已经预留为消融开关。

### 8.2 去重与 small-to-big

1. **同小节去重**：同一父块的多个 chunk 只保留得分最高的一个，避免 6 个上下文名额被同一节占满；
2. **small-to-big**：检索用小块（精确），喂给大模型时扩展为同小节全文（完整）。引用展示的仍是被命中的**精确小块**，保证出处可核查。

## 10. 可回答性判定与拒答（本方案的核心）

这是整条链路里最难也最关键的一环。前两版的失败与修正过程，本身就是最重要的一课。

### 10.1 判据一：实词加权覆盖率 `wcoverage`

$$w_c = \frac{\sum_{t \in Q \cap C} w(t)}{\sum_{t \in Q} w(t)}, \qquad w(t) = \text{IDF}(t) \cdot \log(1 + |t|)$$

- IDF 让**在语料中没出现过的词**获得最高权重——问"红烧肉怎么做"时，"红烧肉"IDF 拉满却匹配不上，覆盖率会直接塌下来；
- `log(1+词长)` 让**长实词**比短词更重要；
- **弱词权重为 0**：纯数字、单字中文、两字符以下英文。否则问"2024 年诺贝尔物理学奖颁给了谁"时，"2024"和"年"恰好出现在语料里，会贡献大半个权重，让系统误以为"有依据"。

> **修正记录**：加入弱词排除前，该题相关性 0.485（超过阈值）；修正后降到 0.200。

### 10.2 判据二：关键实词命中 `key_hit`（结构性规则）

仅靠连续阈值不够。问"红烧肉怎么做才好吃？**请给详细步骤**"时，真正的实词"红烧肉""好吃"一个都没命中，但泛化后缀"详细""步骤"恰好在语料里，能凑出 35% 的加权覆盖率——被误判为"有依据"。

因此增加一条**结构性规则**：**问题中权重最高的两个实词，至少命中一个**。

$$key\_hit = \frac{|\{t : t \in \text{top-2}(Q),\ t \in C\}|}{2}$$

选它而不是继续调连续阈值，是因为**结构性规则不依赖具体分数刻度**：语料换了、规模变了，"top-2 实词至少命中一个"依然成立，而"阈值 0.39"未必。

### 10.3 判据三：提问脚手架词

EV-009"SWEBOK v4.0 一共有多少个知识域？新增了哪几个？"的 top-2 实词是「哪几个」「一共」——**提问脚手架**，不是主题词。它们不该参与可回答性判定。

因此维护一份 `QUESTION_SCAFFOLD` 词表（哪几个/步骤/详细/常见/组成/几类/关系……），这些词：
- **不参与** `wcoverage` 与 `key_hit`；
- **仍保留**在 BM25 与普通 `coverage` 中——因为它们在课程语料的**小节标题**里是有意义的（如"常见误解与易混淆概念"），从索引里删掉反而会伤害检索。

### 10.4 闸门与阈值标定方法论

最终判定（`retrieve.is_supporting`）：

```
可回答  ⟺  wcoverage ≥ min_relevance  且  key_hit ≥ 0.5
```

`min_relevance` 的标定遵循三条纪律：

1. **只在开发集上标定**。评测集按确定性规则划分（ID 数字奇数 → dev，偶数 → test），`scripts/calibrate.py` 只读 dev。这是课程《验收标准》第 6 章的硬性要求。
2. **最大化间隔，而不是最大化 dev 上的 F1**。在 dev 上挑 F1 最高点等价于在 dev 上过拟合。当 `key_hit` 已完全分离两类问题时，相关性阈值退化为第二道防线，取范围内最低分的 70% 保留 30% 余量。
3. **标定结论写回代码并留痕**（`config.py` 注释里写明标定方法与来源）。

dev 集标定结果：超范围问题最高分 **0.000**（全部被 `key_hit` 拦下），范围内问题最低分 **0.568**，取 `min_relevance = 0.39`。

## 11. 四层护栏

对应验收标准 5.3，采用"威胁 × 位置 × 措施 × 测试"的护栏矩阵：

| 层 | 威胁 | 措施 | 测试 |
|---|---|---|---|
| **输入** | 提示注入、提示词泄露、越狱 | 13 条正则模式，命中即拦截，**不进入检索与生成** | `tests/test_guardrails.py::test_injection_is_blocked`（10 例）+ EV-201~206 |
| **输入** | 测验作弊诱导 | 8 类模式（动词前后两种语序都覆盖），拒绝给出答案并给出学习路径 | `test_cheating_is_refused`（6 例）+ EV-301~306 |
| **检索** | 课件夹带指令 | 逐行净化，剔除含指令模式的行，**被剔除的行写入 trace** 供红队复盘 | `test_sanitize_evidence_strips_embedded_instructions` |
| **检索** | 语料作为数据而非指令 | `<<<EVIDENCE ... EVIDENCE>>>` 定界符 + 系统提示明确声明 | 提示词规则 2 |
| **输出** | 引用不存在的编号 | 解析全部 `[n]`，越界编号**直接删除**并记录准确率 | `test_validate_citations_detects_invalid_reference` |
| **输出** | 结构化输出不合 schema | Pydantic 请求校验（空问题返回 422） | `test_tutor_ask_rejects_empty` |
| **动作** | 改成绩 / 未经批准推送干预 | **不提供任何写操作工具**，RAG 层只读 | 架构约束（NF-12） |

**关于提示词泄露**：拦截后返回固定话术，回答中**绝不包含**系统提示词内容——这一点有专门的端到端断言（`test_injection_is_blocked_end_to_end`）。

## 12. 可观测性与成本

每次调用写入 `data/logs/trace.jsonl`，按 `trace_id` 可完整回放：

```
输入摘要 · 护栏判定 · 检索结果（每条的稠密/稀疏排名、RRF、coverage、wcoverage、key_hit）
      · 提示词版本 · 模型 · token · 耗时 · 估算费用 · 是否降级 · 引用校验结果 · 被剔除的指令行
```

- `GET /api/trace/{trace_id}` —— 按 ID 查单次调用（AC-NF-14）
- `GET /api/cost/report` —— 按功能汇总调用次数、token、费用、平均延迟、拒答数、护栏拦截数（AC-NF-4）
- `GET /api/debug/retrieve?q=` —— 查看检索中间结果，用于误差分析
- 模型价格表内置常见模型，未知模型按 0 计并标为估算。

## 15. 已知局限（必须如实报告）

1. **语料规模不足**。只有 5 篇讲义、39 个知识点，缺《软件工程》最常被问到的**软件测试**章节（等价类划分、边界值分析、覆盖准则等）。当前问"等价类划分是什么"会被**正确拒答**——这恰好证明了拒答机制在工作，但对教学场景是明显的内容缺口。补法是往 `kb/docs/` 放一篇 Markdown + 对应 meta JSON，重建索引即可，无需改代码。

2. **消融实验无区分度**（§13.3）。语料小 + 评测题与讲义用词高度重合，导致所有配置都满分。要得到有意义的消融结论，需要：语料扩大到 2 章以上真实课件、评测题改写为口语化提问、并加入干扰项。

3. **评测集规模未达课程要求**（36/8/12 vs 要求的 ≥40/≥10/≥10）。

4. **特征设计过程见过全量评测集**。阈值标定严格只在 dev 上进行，但 `wcoverage` 的权重、弱词与脚手架词表、`key_hit` 规则，都是在**反复查看全量评测集错误样例**的过程中迭代出来的。因此 test 子集上的 1.000 是**乐观估计**，不是无偏估计。严格做法是：先冻结一份从未看过的评测集，再做特征迭代。这一点在 mini-paper 的"局限"一节必须写明。

5. **离线后端不是智能体**。`provider=offline` 的抽取式回答只用于本地跑通与单元测试，输出上都有显式标注。课程验收要求 AI 功能真实调用大模型（否决项 X1），交付时必须设置 `SE_RAG_LLM_PROVIDER=openai`。

6. **拒答判据仍是词面的**。`wcoverage` 与 `key_hit` 都建立在词汇重合之上，对"换了说法但意思相同"的越界问题（如用同义词描述课程外内容）可能失效。下一步可引入基于嵌入的 OOD 检测（如 Mahalanobis 距离）或小模型分类器。

7. **重排未使用 cross-encoder**，单一模型实例、无向量数据库。语料扩大到数万 chunk 时，`RagIndex` 的全量矩阵乘法需要替换为 FAISS/pgvector。
