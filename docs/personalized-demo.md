# 演示学生画像与个性化答疑

本功能是课程作业的**受限演示**。`student01` 和 `student02` 在预置“软件工程基础”课程中拥有两份不同的模拟学习历史；没有正式测验成绩来源，不能把正确率、错题或薄弱点称为实际学习记录。其他课程与账号仍等待正式业务接入。

## 学生看到什么

- 登录学生账号，打开“软件工程基础 → 学习报告”。基础模式展示每章的正确率、错误率、错题及模拟作答、薄弱知识点和建议练习。正确率低于 60% 的章节标为“错误率较高”。
- 打开“资源学习”，默认选中“全部内置讲义 · AI 问答”，可以向真实模型提问；也可选择一份讲义缩小资料范围。内置 Markdown 资料目前没有浏览器预览地址；引用显示文档与章节，不虚构页码或视频秒数。
- 在学习报告底部提问使用同一服务。两名学生询问同一个需求概念时，模型收到的模拟历史不同，因此应分别针对“混淆功能与质量约束”和“缺少可测量指标”给出练习建议。
- 5E 模式、增强推荐和正式诊断追问仍返回 501，不把模拟历史当作已计算的画像。

## 上下文接入规则

后端先对本次问题运行课程讲义检索。资料不足时按原有 RAG 规则拒答，不调用模型。资料可用时，只考察本次检索片段所关联的知识点；其相关性至少为 `0.55`、同时通过原有可回答性校验，且名称与当前学生历史中的 `rag_topic` 相同，才加入最多两个薄弱点。加入内容仅含该章正确率、错题、模拟作答、薄弱原因和建议练习。无匹配时不传任何模拟历史。用户不能在请求中指定其他人的画像，账号来自服务端会话。

提示词把模拟历史标为“只用于调整讲解方式”，课程知识结论仍必须依据检索到的讲义引用。响应的 `personalization` 字段列出本次匹配的知识点和最高相关性；页面据此标注。历史不会因为提问自动修改。提问本身以实际登录用户 ID 和课程 ID 写入 `asked` 事件及模型 trace。

## 接口状态

前缀为 `/api/v1/courses/{course_id}`，需要登录与课程成员权限；写请求需要 Origin 与 CSRF token。

| 接口 | 演示课程中的实现 | 其他范围 |
|---|---|---|
| `GET /resources` | 返回内置讲义目录，`url=null` | 501 |
| `POST /chat` | 预置学生的 `mode=rag` 调用真实模型；`resource_id=kb:all` 或 `kb:SE-xx` | 其他课程或 5E 为 501 |
| `GET /report` | 预置学生的 `algorithm=baseline` 返回 `history_source=synthetic`、`chapter_history`，其他正式报告数组为空 | 增强推荐及其他范围为 501 |
| `POST /report/followup` | 预置学生按全部讲义提问，返回同一 `ChatOut` | 其他范围为 501 |

没有 API Key 或模型暂不可用时，问答会明确报错；不会伪装成真实成功。模型失败时保留提问事件与 trace。当前仍没有正式题库、资源上传、媒体预览、多轮会话状态、画像计算和推荐算法。
