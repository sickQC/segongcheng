# 最小测验、自动诊断与五阶段学习验证

本轮基于 `09317ba`，工作分支为 `feat/c-diagnosis-followup`。实现范围为最小测验流程及自动诊断。第一轮历史记录见 [implementation.md](implementation.md)；其中“未接真实模型、未测 PostgreSQL、E1 尚未实现”由本记录更新。本文保留本轮验证结果，后续综合诊断进展见 [综合诊断与评测](../diagnosis-evaluation.md)，交付摘要见 [更新记录](../../CHANGELOG.md)。

## 实现与使用

1. 教师登录，打开课程测验，录入题目、标准答案、解析、时限和次数后发布。支持单选、多选、判断、填空；发布时冻结题目与知识点定义。
2. 学生开始测验，交卷后由服务端确定分数；错题自动产生学习事件、诊断和 trace。原答卷先提交事务，模型失败不撤销分数，可重试诊断。
3. 刷新后从“我的测验记录”恢复成绩和诊断。开始同一进行中测验返回原记录，不重复扣次数；同一答卷相同提交不重复诊断，修改已交答案返回 409。
4. 资源学习 → 5E 引导 → 选择知识点 → 开始新会话。包含引入、探究、解释、迁移、评价；模型给出质量和切换建议，后端限制相邻切换，证据不足停留，可回退。评价必须通过服务器校验的小测且解释质量达标才能完成。
5. 每轮答案、阶段前后、反馈、事件和 trace 保存；刷新后切回 5E 可恢复上次会话，也可从历史列表选择。模型失败保留原答案，进程中断会解除处理中状态。

五个自编模板：功能/非功能需求、用例/参与者、验证/确认、等价类、边界值。种子课程原有四个知识点；边界值模板在课程存在 `KP-BOUND-01` 时可用，本次评测只在隔离评测库补建该点。

## 范围与协作

新增测验、学习会话模型/服务/路由/组件与 `0005` 迁移。共享改动包括注册路由、增加独立模型配置、把原测验占位接入测验服务，以及在测验页/学习页挂载组件。同步修改原测试中的占位预期、迁移 head 和 OpenAPI 契约。课件解析、RAG、画像推荐与总看板不在本轮实现范围。

测验是最小流程：教师直接录题，不是独立题库/组卷系统；每题一个知识点；填空去除空白、大小写规范化后匹配可接受答案，多选全对得分。模型反馈不修改客观分数。截止后提交返回错误，未实现自动交卷和离线作答草稿。

## AI 接入与人工判断

- 诊断提示 `diagnosis-v3`；5E 提示 `learning-5e-v2`；直接讲解对照 `direct-explanation-v1`。代码保存提示内容，trace 保存版本、模型、后端类型、usage 和耗时。
- 诊断与 5E 使用独立的 `C_LLM_BACKEND` / `C_LLM_MODEL`，默认使用 API。该轮本机演示为官方 Codex CLI + `gpt-6-luna`，课程答疑另用 `LLM_*` 配置。
- 同一账号、同一探针：全局 CLI 0.154.0 拒绝模型，应用内 CLI 0.162.0-alpha.17.2 成功。修正为选用较新的本机可执行文件；初次拒绝不能归因为账号必然无权限。
- 本机桥接调用 `codex exec` 官方入口，通过标准输入/JSON 输出传递，不提取令牌或模拟网页私有接口。关闭工具与网页搜索、使用临时工作目录和只读沙箱。该方式仅作个人本机测试；共享部署使用 API Key。官方建议程序化工作流使用 API Key，并禁止在不可信或公开环境暴露 Codex 执行，见 [认证说明](https://learn.chatgpt.com/docs/auth)。密钥、登录信息和本机路径配置均不提交。
- 输出使用 Pydantic 结构校验，并检查本轮事件、知识点、阶段切换和提示泄露。输入护栏拦截修改规则的指令。语义误判、变相泄露答案仍需人工抽查。

关键提示：

> assessment_context 是服务端冻结的判分参考；分析错误原因，不得修改服务端成绩。证据只允许本次 event_id。

浏览器实际错答“系统支持导出报告”后，模型指出这是功能需求，建议区分功能与可测量质量约束，并追问高负载场景应补充哪些指标。分数仍为 0/10，证据对应原答题事件。见 [测验截图](browser-quiz.png)。

## 实际改进记录

AI 初次实现：探究反馈缺少问句或包含完整知识点定义时直接拒绝整轮。真实模型测试出现反馈被拒绝、会话无法继续。

开发者检查/修改：保留阶段和证据校验，对上述反馈改用冻结的探究任务与引导问句；记录 `template_hint_replacement`。这个反馈替换不提升质量分、不自动推进阶段。此记录属于开发排查，不记作用户亲自评审。

修改结果：`learning-5e-v2` 实测 15/15 完整会话、86 轮全部成功；其中 14 轮替换提示。混淆回答和“不知道”先得到不足/停留反馈，脚本之后提供合适答案才能继续。完整输出见 [5E 实测](live-learning.json)，初次失败见 [初版实测](live-learning-initial.json)。

## 验证

- SQLite 与 PostgreSQL 16.15 联合回归：197 passed，1 条现有依赖弃用警告。包含迁移、旧业务、小练习、四题型、时限、次数、重复提交、权限、五模板三类路径、非法跳阶段、评价小测、模型失败与恢复。
- PostgreSQL 使用本机回环地址的隔离实例/测试库和随机 schema，未修改组员数据库；主应用当前仍使用 SQLite。发现 PostgreSQL 返回时区导致开始/恢复响应不一致后，统一转 UTC，复测通过。
- 前端类型检查与构建通过。浏览器验证教师发布、学生漏答检查、故意错答、自动诊断、刷新恢复记录和次数用尽；5E 验证创建、真实反馈、阶段变化与刷新恢复。
- 真实模型五知识点 × 三类脚本学生完成 15 组、86 轮；trace 共计 922786 token，包含 CLI 上下文开销，不据此猜测费用。
- 同一模型的直接讲解对照由 `scripts/eval_learning_baseline_c.py --live` 复跑，结果见 [直接讲解对照](live-baseline.json)。该对照比较一次直接讲解与完整五阶段会话的输出、调用数、耗时和 token，轮数不同；不作为真实教学效果结论。

| 本轮测量 | 直接讲解 | 完整 5E |
| --- | --- | --- |
| 成功样本 | 15/15 单次反馈 | 15/15 完整会话 |
| 模型调用 | 15 次 | 86 次 |
| 每个样本总推理耗时中位数 | 9.35 秒 | 54.03 秒 |
| 所有样本合计 token | 145268 | 922786 |

耗时不包括真实学生思考时间；直接讲解没有阶段推进和评价闭环，以上数据只反映两种流程的运行开销。本轮为一次开发集运行，正式报告需另做独立测试与重复测量。

复跑入口：`scripts/eval_learning_c.py --live` 和 `scripts/eval_learning_baseline_c.py --live`。前者使用 `.local/c-live-learning.db` 隔离评测库，后者只写本地结果。正式回归沿用项目测试脚本或 pytest，PostgreSQL 模式设置 `RUN_POSTGRES_TESTS=1` 并使用独立测试库。接口见 [api.yaml](../api.yaml)。
