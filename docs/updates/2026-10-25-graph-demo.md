# 学生知识图谱演示

按课堂演示需求新增独立前端页面，不接入真实课程图谱或学生学习记录。

学生登录后，在课程目录、资源学习/学习报告的导航或左侧菜单点击“知识图谱（演示）”。路由为 `/#/courses/{course_id}/graph-demo`，沿用学生登录校验，教师不显示该入口。页面始终标明“演示数据”，所有课程展示同一份软件工程样例。

## 演示步骤

1. 默认“测试薄弱”情景，选择“边界值分析”，点击“演示推荐路径”：安排等价类划分、边界值分析两步，图中蓝色描边和编号标识顺序。
2. 切为“初学者”：所有掌握度显示未知，路径加入软件测试基础和黑盒测试，共四步。
3. 切为“大部分已掌握”：仅安排边界值分析；已达标的目标显示无需新步骤。
4. 搜索知识点或按章节筛选，使用缩放按钮及图谱区域滚动查看节点。点击节点展示定义、例子、先修及后续节点。
5. 点击“体验示例练习”，选择答案并查看解析。练习不会改变演示掌握度；重新选择节点可重置该练习。
6. 点击“重置演示”或刷新页面恢复默认情景。切换情景或目标会清除之前的路径，需重新点击演示。

## 数据范围

- `frontend/src/api/graphDemo.ts`：17 个知识点、16 条关系、模拟分数及本地路径计算。三组分别为需求分析、软件设计、软件测试；关系是课堂示例，不代表完整教学依赖。
- 统一以“先修 → 后续”表示箭头，未知分数为 `null`；示例阈值固定 70%，不读取正式环境阈值。路径先计算完整先修顺序，再过滤已掌握节点。
- 样例 ID 不与数据库知识点绑定；没有真实资源或诊断入口，示例练习仅在当前页面展示解析。
- 图谱交互不请求正式画像、先修关系、推荐或测评接口，不使用 localStorage，不保存作答、掌握度、点击记录或推荐。外层应用仍正常执行登录、课程导航和健康检查。
- 本轮没有改动后端或数据库，不需要迁移。原有真实学习报告及推荐模块继续使用原数据。

## 验证

- 前端 TypeScript 检查及 Vite 生产构建通过，保留既有包体积提示。
- 三项算法回归覆盖节点/边完整性、先修方向、未知掌握度、分叉先修闭包、已掌握过滤、无效目标及演示数据不被修改，入口为 `npm run test:graph --prefix frontend`（Node 22）。CI 前端任务已增加该检查。
- Edge 浏览器验收通过：`tests/browser-graph-demo.cjs` 使用隔离账号，检查导航、情景路径步数、搜索及章节筛选、示例练习、缩放、刷新重置、390px 移动布局，并断言图谱不产生课程写请求、页面无脚本错误。通过 `TEST_BASE_URL`、`TEST_PASSWORD`、`PLAYWRIGHT_MODULE` 指定测试环境。

当前机器为 Node 20，算法回归使用本机 TypeScript 将相同源码和测试转为临时 ES 模块后执行，三个用例通过。CI 的 Node 22 可以直接运行测试入口；新增 CI 尚未推送执行。已知其他后端 CI 配置问题不属于本轮图谱演示改动。
